# 004 — M0 项目样例集（合法 / 非法 / 边界）

- 状态：todo
- 目标：在 `examples/` 建立覆盖设计基线 §12.1 十二类场景的项目样例，每个非法样例带预期诊断代码，
  作为 M1 的验收测试数据。
- 授权：Extend（仅 `examples/`）
- 变更声明：无（仅 `examples/`；目录已由 001 建立）

## 背景

设计基线 §12.1 要求为 12 类错误与边界准备样例，但仓库里还没有任何项目目录。样例既是
M0 的交付物，也是 M1 解析 / 校验的回归数据；没有样例，冻结的 Schema 无法被证明可执行。
样例必须在 002 / 003 之后建立，避免字段名与错误代码返工。

## 清单

- [ ] `minimal-project/`：一个 Root + 一个叶子模块
- [ ] `nested-composition/`：≥3 层 Composite 与 Primitive
- [ ] 多实例复用：同一 Module Definition 被多个 Instance 使用
- [ ] Slot 基数边界：必需 Slot 缺失 / 单 Slot 重复接入 / many Slot 合法接入
- [ ] 非法引用：Module / Instance / Slot / Port 不存在
- [ ] 属性错误：未知属性、类型错误、枚举值错误、缺少必填属性
- [ ] 结构错误：多个 Root、孤立实例、多父节点、重复 Binding
- [ ] 版本错误：模块版本缺失或指定版本不可用
- [ ] 文件错误：入口缺失、路径越界、TOML 语法错误
- [ ] 编辑错误夹具：事务中一条命令失败、Revision 过期、重复 request ID（M2 使用）
- [ ] 外部修改场景：合法 / 非法 / 与未保存内容冲突（M3 使用）
- [ ] 格式保留样例：含注释、空行、不同字段顺序的 TOML
- [ ] 每个样例目录的 README：目的、预期诊断代码、M1 起的验证命令
- [ ] 根 README 的覆盖清单与设计基线 §12.1 映射

## 验收

- 12 类每类至少 1 例，目录与命名可被测试扫描；
- 每个非法样例声明预期错误代码（来自 003），且与错误代码表一致；
- 合法样例满足 003 的全部必填与约束（当前人工核对；M1 起由 CLI 验证）；
- 不包含 `.designer/` 布局，除非样例专门验证 A15（Canvas 隔离）；
- 样例目录结构与设计基线 §4.1 一致，入口固定为 `project.toml`。
